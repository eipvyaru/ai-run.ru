# Готовность ASR к release и развёртыванию

Дата проверки: 01.11.2026

Проверенный implementation/deployment commit: `c92561b12d074bde9fae2d5f31bdca7856f6c62f`

Модель: `sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16`, revision `a6039be7cee829a9044a69ac0ebaf1c191217c97`.

Этот отчёт отделяет локальную готовность исходников от непроверенных условий VPS. Код, конфигурация и инструкции готовы к deployment на указанном commit. Sherpa нельзя включать для посетителей до проверки Linux runtime, FFmpeg, готовности модели и фактической памяти VPS.

## Что поставляется

- Переключатель browser/Sherpa, режим Sherpa по умолчанию для первой миграции, настройка в админке.
- Запись максимум 60 секунд, ручная остановка, VAD-остановка, обработка тишины и ограничение частоты/очереди.
- Sherpa Python service на loopback `127.0.0.1:8794`; модель загружается один раз, файлы проверяются по SHA-256 manifest.
- Один fallback на браузерное распознавание с уже записанным аудио, если браузер это поддерживает; иначе ошибка и обычный текстовый ввод без повторной диктовки.
- Редактируемый черновик; голосовой результат не отправляется автоматически. До согласия запись/отправка аудио запрещена.
- Админ-панель показывает режим/readiness; отдельный защищённый журнал отображает последние 1000 безопасных событий и поддерживает фильтры/CSV/подтверждаемую очистку.
- Секрет приложения и минимальная среда Python передаются отдельно; модель, записи, SQLite, prompt и секреты в Git не входят.
- Отдельный systemd unit, ограниченный Nginx-маршрут upload и обновлённые инструкции первого deployment, update и rollback.

## Ограничения доказательств

- Локальная сквозная модельная проверка выполнена на Windows. Наличие и совместимость Linux wheels на Ubuntu VPS пока не подтверждены; перед запуском выполнить установку pinned requirements в чистом venv на сервере.
- Browser microphone flow, выдача разрешения и fallback из реального browser MediaRecorder в этом acceptance run не выполнялись. Существующие автоматические тесты проверяют capability gating, запрет неподдерживаемых/mobile API и отсутствие повторного запроса микрофона; фактическое поведение остаётся browser/version-dependent.
- UI просмотрен на desktop viewport. Встроенный browser viewport override не изменил фактический размер страницы, поэтому мобильный screenshot/layout здесь не заявляется; mobile CSS breakpoints реализованы, но требуют проверки в реальном Chrome DevTools/device viewport.
- Не проводились production deployment, настройка Nginx/systemd, публичные запросы к VPS, реальные платные интеграции, нагрузочные испытания или действия с production data.

## Условия перед включением Sherpa на VPS

Read-only аудит на момент планирования показал Ubuntu 24.04 x86_64, Python 3.12.3, отсутствие FFmpeg, занятый порт 8793 и свободный loopback-порт 8794. На VPS было около 932 MiB RAM всего и около 382 MiB доступной при аудите. Это снимок на время проверки, не гарантия текущего свободного объёма; веса модели могут увеличить memory pressure.

До включения Sherpa на production необходимо:

1. Повторно сверить текущий VPS commit, backup/checkpoint согласно deployment-процедуре, RAM/swap/диск, состояние приложения и занятость `8794`; не менять другие сайты и службы.
2. Установить FFmpeg и проверить закреплённые Python 3.12.3 Linux wheels без обновления версий по `latest`.
3. Передать модель отдельно и проверить каждую SHA-256. Секреты передать отдельно с минимальными правами; не помещать их в команды/логи/Git.
4. Запустить только ASR unit на loopback, проверить `/health` и `/ready`, сделать один smoke и три последовательных decode на неперсональном WAV.
5. Замерить peak RSS/CPU холодного старта и decode, проверить работу web-сервиса при обычной нагрузке. Не задавать `MemoryMax`, пока не измерено потребление. Если есть риск OOM — оставить активный режим browser и ASR-службу выключенной.
6. Только после успешных проверок применить точный release commit и конфигурацию сайта ai-run.ru, проверить `nginx -t` и diff; затем проверить режим, fallback и журнал.

Подробные команды и rollback находятся в [`ASR_OPERATIONS.md`](ASR_OPERATIONS.md), [`DEPLOYMENT_ROOT.md`](DEPLOYMENT_ROOT.md) и [`DEPLOYMENT_UPDATE.md`](DEPLOYMENT_UPDATE.md). Этот отчёт не является разрешением на deployment. Push/deployment не выполнялись.
