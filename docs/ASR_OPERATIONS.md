# Эксплуатация распознавания речи Sherpa

## Состав поставки

- Модель: `sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16`, revision `a6039be7cee829a9044a69ac0ebaf1c191217c97`.
- Python: 3.12.3; версии библиотек закреплены в `asr/requirements.lock`.
- Python API в systemd deployment слушает только `127.0.0.1:8796`. В Docker он доступен только в закрытой сети `ai-run-internal-services`, без опубликованного host-порта.
- Веб-приложение обращается к Python через Node Route Handler; Nginx проксирует только `/api/asr/transcribe` на веб-приложение и не имеет маршрута к Python.
- Модель, секреты, виртуальная среда, записи и production-данные не входят в Git.

## Переменные окружения

Локально `.env` — источник секрета `ASR_SERVICE_TOKEN`. Выполнить `scripts/sync-vps-env.ps1`: скрипт при необходимости создаёт случайный токен, пишет production env приложения в игнорируемый `data/.env.vps` и минимальный env Python в `data/.env.asr.vps`; значения не выводятся. Передавать эти файлы отдельно и только по защищённому каналу:

- `data/.env.vps` → `/var/www/ai-run.ru/.env`;
- `data/.env.asr.vps` → `/var/www/ai-run.ru/.env.asr`.

Для Docker Compose используются значения из корневого `.env`; `ASR_SERVICE_URL` переопределяется на `http://asr:8796`, а тот же токен передаётся обоим контейнерам. Не запускайте контейнерную и systemd ASR-службы с одним host-портом одновременно. Подробности: `docs/DOCKER_DEPLOYMENT.md`.

На сервере оба файла должны быть доступны только соответствующей службе и root (ориентир `0600`, владелец `root`; для Python-файла можно использовать отдельную группу службы с `0640`). Токен в обоих файлах должен совпадать. После ротации заменить оба файла и перезапустить сначала ASR, затем веб-службу. Не помещать копии в Git, команды, историю терминала, сообщения или журналы.

## Установка при первом deployment

1. До любых изменений повторно проверить свободную RAM, диск, порт 8796, системные версии Python и архитектуру. Порт 8794 не использовать: он зарезервирован в центральном реестре под Playwright для privacy-service. Установить `ffmpeg` из системного Ubuntu-репозитория; проверить `/usr/bin/ffmpeg -version`.
2. Убедиться, что Python 3.12.3 доступен как `/usr/bin/python3.12`; создать `/var/lib/ai-run.ru/asr/venv` и установить зависимости из `asr/requirements.lock`. Установку Linux wheel проверить до включения службы: локальная Windows-проверка не доказывает наличие Linux wheel.
3. Создать непривилегированные пользователя/группу `ai-run-asr`, каталог `/var/cache/ai-run.ru/asr` с владельцем `ai-run-asr` и режимом `0700`.
4. Отдельно передать четыре файла модели `encoder.int8.onnx`, `decoder.onnx`, `joiner.onnx`, `tokens.txt` в `/var/lib/ai-run.ru/asr/models/gigaam-v3-punct`. Пример WAV для smoke-теста положить рядом в `test_wavs/example.wav` только если он взят из утверждённого локального источника. Выставить каталоги `0750`, файлы модели `0640`, владельца root и группу `ai-run-asr`.
5. Сверить файлы с `asr/model-manifest.json`. Перед первым запуском выполнить smoke по инструкции ниже; readiness отклонит другую версию или изменённый вес.
6. Установить `/var/www/ai-run.ru/.env` и `.env.asr` с ограниченными правами. Проверить совпадение токена без вывода его значения.
7. Установить `deploy/systemd/ai-run-ru-asr.service` в `/etc/systemd/system/`, проверить пути и разрешения, выполнить `systemctl daemon-reload`, включить и запустить только `ai-run-ru-asr.service`.
8. Проверить `systemctl status ai-run-ru-asr`, `curl --fail http://127.0.0.1:8796/health` и `curl --fail http://127.0.0.1:8796/ready`. Извне VPS этот порт должен быть недоступен.
9. Установить конфигурацию сайта из `deploy/nginx/ai-run.ru.conf`, проверить `nginx -t` и применить reload только после подтверждения, что diff меняет только `ai-run.ru`. Путь `/api/asr/transcribe` допускает 9 MiB multipart; Python endpoint не проксируется.
10. Применять проверенный web release и миграцию по `docs/DEPLOYMENT_ROOT.md` / `docs/DEPLOYMENT_UPDATE.md`. Проверить веб readiness, вход в админку, режимы и журнал. Выбор `sherpa` включать после проверки readiness.

### Обязательное измерение памяти

Предыдущий read-only аудит VPS показал около 932 MiB RAM всего и порядка 382 MiB доступной памяти при аудите. Это значение не является текущей гарантией. До запуска модели сверить `free -h`, `systemd-cgtop`, `MemAvailable`, swap и нагрузку приложения. Запустить ASR отдельно, записать `MemoryPeak`/RSS и CPU для холодной загрузки и трёх последовательных запросов, затем проверить сайт под обычной нагрузкой. Не назначать `MemoryMax` до этих измерений; не продолжать включение Sherpa, если процесс провоцирует OOM или ухудшает доступность веба. В таком случае оставить режим `browser` и планировать отдельное согласованное ресурсное решение.

## Smoke и диагностика

Локальная Windows-машина с точным источником модели:

```powershell
$env:ASR_MODEL_DIR = 'C:\_Codex\_Models\sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16'
$env:ASR_TEST_WAV = Join-Path $env:ASR_MODEL_DIR 'test_wavs\example.wav'
& data\asr-runtime\.venv312\Scripts\python.exe scripts\verify-asr-model.py
Remove-Item Env:ASR_MODEL_DIR, Env:ASR_TEST_WAV
```

Smoke проверяет revision и SHA-256 четырёх файлов, целостность sample WAV и непустой результат; выводит только длину текста и время, сам транскрипт не печатает. На VPS запускать тот же скрипт с корректно установленными путями. Если тестовый WAV не устанавливается, выполнить такой же защищённый запрос через одобренный неперсональный тестовый файл; не брать реальную запись пользователя.

- `/health` успешен, `/ready` нет: проверить `journalctl -u ai-run-ru-asr` на безопасный код; чаще всего модель, права или токен запуска.
- `ASR_BUSY`: очередь занята; приложение возвращает управление к уже записанному аудио и fallback-пути. Не увеличивать число параллельных decode без замеров RAM.
- `ASR_NOT_READY`: проверить ready и зависимости модели; при недоступности выбрать browser в админке.
- `ASR_TIMEOUT`: проверить CPU, FFmpeg и длительность; аудио/транскрипты из журналов не копировать.
- временные файлы: штатно удаляются после запроса; после аварийного завершения проверять только имена/возраст и удалять старые файлы по отдельной проверенной процедуре.
- журнал в админке содержит только ограниченные технические enum-события; он не заменяет серверные логи и ограничен 1000 записями.

## Обновление и rollback

Модель обновлять отдельной версионированной директорией. Сначала зафиксировать revision и SHA-256 в новом manifest, установить веса рядом, выполнить настоящий smoke и оценить память. Переключить `ASR_MODEL_DIR` только после успешной проверки, перезапустить только ASR unit и проверить `/ready`; старую директорию оставить до завершения наблюдения. Применение новой архитектуры/модели требует отдельного изменения и проверенного commit.

При отказе переключить приложение в `browser` через админку, остановить только ASR unit для сохранения RAM, исправить или вернуть модельную директорию к предыдущей версии и перезапустить только ASR unit. Web rollback выполнять по `docs/DEPLOYMENT_UPDATE.md`, не откатывая SQLite и не заменяя consent evidence, `.env` или system prompt.
